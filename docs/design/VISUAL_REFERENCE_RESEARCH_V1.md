# LifeOS — Visual Reference Research V1

Status: APPROVED VISUAL RESEARCH INPUT
Updated: 2026-08-27
Purpose: guide Figma AI / product designers toward a consumer-life-product visual language and away from an overly visible AI-system aesthetic.

## 1. Main conclusion

LifeOS should look like a beautiful daily-life product first and an AI product second.

AI/intelligence should usually be ambient, implicit, and expressed through better organization, timing, prioritization, recovery, and explanation on demand.

Do NOT decorate the product with AI branding everywhere.

Preferred mental model:

`Tiimo warmth + Things restraint + Structured temporal clarity + Sunsama intentional rituals + selective Lifestack context intelligence + modern consumer-app polish`

Not:

`AI dashboard + confidence badges + evidence chips + assistant panels everywhere`.

## 2. Tiimo — strongest mobile emotional reference

Official: https://www.tiimoapp.com/
Visual planning: https://www.tiimoapp.com/product/visual-planning

What to learn:

- very generous white space;
- large editorial/serif-style page titles mixed with clean sans-serif UI text;
- playful but restrained pastel surfaces;
- pill section headers that create quick visual grouping;
- floating/pill-shaped bottom navigation;
- large, obvious creation affordances;
- friendly iconography and occasional character/illustration personality;
- day/date context is visible without turning into a dense calendar dashboard;
- input feels lightweight and native to daily life;
- rounded surfaces feel soft without excessive glassmorphism;
- AI/co-planning exists but the whole product does not look like an AI control room.

What NOT to copy literally:

- Tiimo's exact mascots/brand assets;
- exact typography/color palette;
- every calendar/routine interaction;
- streak/gamification semantics that do not fit LifeOS.

LifeOS adaptation:

- use editorial headings for major contexts such as NOW, Thursday, Current Season, Weekly Reset;
- use soft tinted sections for life states/categories;
- allow playful small iconography for Capture/Focus/Not Now;
- keep AI visually backstage.

## 3. Things 3 — restraint and invisible chrome

Official: https://culturedcode.com/things/

What to learn:

- typography and spacing do most of the hierarchy work;
- controls recede until needed;
- lists are readable because chrome is minimal;
- one accent color can carry most interaction priority;
- deep product capability does not require heavy cards, dashboards, or visible system explanation;
- delightful micro-interactions can exist without visual noise.

LifeOS adaptation:

- reduce card borders and AI-specific labels;
- let important copy breathe;
- use inline controls and progressive disclosure;
- avoid wrapping every data point in a chip.

## 4. Structured — visual time and approachable planning

Official/help: https://structured.app/ and https://help.structured.app/

What to learn:

- time is made spatial and visual through a timeline;
- color/icon combinations help users scan the day quickly;
- tasks can feel like activities, not database rows;
- mobile interaction is optimized around today's reality.

LifeOS adaptation:

- Focus / Daily Close / recovery views may use lightweight temporal cues;
- use icons/color to distinguish context without requiring more reading;
- do not turn EXECUTE into a spreadsheet-like project manager.

## 5. Sunsama — calm rituals and intentional planning

Official: https://www.sunsama.com/
Daily planning: https://www.sunsama.com/daily-planning
Today view documentation: https://help.sunsama.com/docs/usage-guides/today-view/

What to learn:

- guided planning can feel like a calm ritual rather than setup work;
- workload/capacity is surfaced to prevent overcommitment;
- “what can wait?” is a first-class planning decision;
- Today view becomes the work surface after planning;
- planning and shutdown/review are narrative flows rather than analytics walls;
- desktop can be deep without becoming visually aggressive.

LifeOS adaptation:

- Weekly Reset should be a guided story;
- Clarity / Current Season builder should feel like a ritual;
- Not Now should be visually positive/safe;
- desktop REFLECT can use guided step layouts with subtle supporting context.

## 6. Lifestack — intelligence as context, not chat

Official: https://lifestack.ai/

What to learn:

- intelligence can be expressed as contextual signals/curves/overlays instead of assistant prose;
- a single brand accent can make analytic information approachable;
- a clean white canvas prevents personal-data UI from feeling clinical.

What NOT to copy:

- health/biometric dashboard structure;
- energy scores as LifeOS life scores;
- charts where LifeOS lacks direct evidence.

LifeOS adaptation:

- Personal Operating Model / Weekly Reset may show compact observed patterns visually;
- only visualize measured/confirmed evidence;
- use charts sparingly and only when they reduce understanding time.

## 7. Superlist — expressive but still functional

Official: https://www.superlist.com/
Help: https://help.superlist.com/

What to learn:

- strong typography gives lists personality;
- rich content can live beside tasks without becoming a database UI;
- quick create is obvious;
- mobile/desktop feel related but appropriately adapted;
- visual personality can be stronger than traditional productivity apps.

What NOT to copy:

- list-centric IA as LifeOS mental model;
- collaboration/social/meeting surfaces for MVP.

LifeOS adaptation:

- EXECUTE context may mix outcome/project/action text naturally;
- Inbox/Capture can feel editorial rather than table-like;
- use bold display type selectively.

## 8. Amie — pastel orientation + calendar polish

Official: https://amie.so/

What to learn:

- soft pastel blocks make calendar/time content scannable;
- minimal black/white chrome creates contrast with contextual color;
- mobile composition can feel modern without excessive cards.

LifeOS adaptation:

- semantic pastel tints for Active / Maintain / Not Now / Focus / Reflection;
- do not make color the only state signal.

## 9. Todoist — clarity and capture maturity

Official: https://www.todoist.com/

What to learn:

- fast capture and low-friction creation;
- typography/spacing scales across large amounts of content;
- everyday consumer language instead of technical system language;
- quick-add should remain easy even in a powerful product.

LifeOS adaptation:

- Capture from anywhere should feel lightweight;
- do not force ontology fields at input time;
- advanced context belongs after capture.

## 10. Routine / Akiflow / Morgen — desktop execution references

Routine: https://routine.co/
Akiflow: https://akiflow.com/
Morgen: https://www.morgen.so/

What to learn:

- calendar/task split-view can work well for deeper desktop planning;
- keyboard-first desktop flows can reduce friction;
- quick capture and agenda surfaces can coexist;
- contextual side panels are useful when they do not compete with the central action.

LifeOS adaptation:

- DIRECTION / REFLECT can use contextual rails on desktop;
- NOW should remain simpler than these apps;
- LifeOS should not become a calendar replacement.

## 11. Dribbble task-app research — use as visual material only

Reference search: https://dribbble.com/search/app-task

Useful things to borrow:

- composition;
- card rhythm;
- spacing;
- mobile bottom bar treatments;
- modal/sheet composition;
- tasteful pastels;
- micro-illustration;
- task-detail hierarchy;
- polished empty states.

Do NOT use Dribbble shots as product-behavior evidence.

Common Dribbble failure modes:

- unrealistic density;
- excessive card soup;
- tiny text/tap targets;
- beautiful but non-functional navigation;
- progress charts with fake data;
- too many decorative gradients;
- desktop concepts that cannot responsively collapse;
- app screens optimized for a portfolio image rather than repeated daily use.

## 12. New LifeOS visual formula

### Consumer-first

LifeOS should feel like something a person opens throughout the day, not software they administer.

### Editorial hierarchy

Use large human-readable context headings where useful:

- Hôm nay
- Thứ Năm
- Điều quan trọng lúc này
- Mùa hiện tại
- Một việc để bắt đầu
- Tuần của bạn

Avoid system headings such as:

- AI Recommendation Engine
- Confidence 0.84
- Evidence Layer
- Agent Insight

### Soft semantic color

Use restrained tints for orientation:

- Active — warm/clear accent tint;
- Maintain — neutral gentle tint;
- Not Now — cool/protected tint;
- Focus — focused single accent;
- Reflection — quieter neutral/soft violet/blue family;
- caution/error — semantic but not guilt-inducing.

### Fewer visible cards

Prefer:

- whitespace;
- typographic grouping;
- dividers;
- section pills;
- one dominant surface;
- inline metadata.

Only create a card when it establishes a meaningful interaction/semantic boundary.

### AI invisible by default

Do not place sparkles, AI labels, robot icons, gradients, or “AI generated” tags on ordinary screens.

Use natural product language:

- `Gợi ý`
- `Vì sao việc này?`
- `Tôi chưa chắc phần này`
- `Đã sắp xếp`
- `Có vẻ điều này đang bị chặn`
- `Muốn chỉnh lại?`

AI identity may appear only where provenance matters, such as:

- interpretation currently being generated;
- explanation of a tentative inference;
- provider failure/manual fallback;
- memory/personalization settings.

### Friendly details

Allow small moments of character:

- subtle playful icons;
- tasteful micro-illustrations in empty/recovery states;
- soft motion;
- custom category symbols;
- optional user-selectable visual personality later.

Do not turn LifeOS into a mascot-driven children's product.

## 14. Visual anti-patterns for Figma AI

Reject a design if it contains several of these at once:

- glowing purple AI orb as persistent primary control;
- sparkles on every recommendation;
- assistant avatar on every page;
- AI chat right rail always open;
- confidence badge on every item;
- evidence chips always visible;
- every row inside a rounded card;
- giant gradients/glass panels;
- three or more charts on NOW;
- technical ontology words exposed to the user;
- dense task/project dashboard as home;
- 6–10 competing CTAs;
- red overdue counts used as pressure;
- “productivity score” or “life score” hero number;
- dark cyberpunk appearance as default.

## 15. Visual acceptance test

A successful LifeOS screen should still look coherent if all words `AI`, `agent`, `confidence`, and `evidence` are removed.

A person should perceive:

1. where they are;
2. what matters;
3. the next useful choice/action;
4. what can safely be ignored;
5. how to correct the system when needed.

The intelligence should be felt through the experience before it is named in the interface.
